# FE 문서

처음 프로젝트에 참여한다면 루트 [README](../README.md)에서 실행 방법을 확인한 뒤 아래 문서를 읽습니다.

## 문서 목록

| 문서                                         | 내용                                    | 변경 시점                                    |
| -------------------------------------------- | --------------------------------------- | -------------------------------------------- |
| [아키텍처](./architecture.md)                | 라우팅, 폴더 구조, 상태 관리            | 화면 구조나 데이터 흐름이 변경될 때          |
| [디자인 시스템](./design-system.md)          | 색상, 타이포그래피, 공통 UI와 접근성    | 디자인 토큰이나 공통 UI 규칙이 변경될 때     |
| [API와 인증](./api-and-auth.md)              | API Client, 인증 갱신, 서비스 접근 제어 | 서버 통신 또는 인증 정책이 변경될 때         |

| [프로젝트 결정 사항](./project-decisions.md) | 핵심 결정과 보류 항목                   | 새로운 결정을 내리거나 보류 항목을 확정할 때 |

## 관리 원칙

- 문서는 현재 구현과 합의된 정책을 설명합니다. 확정되지 않은 내용은 결정 사항의 보류 항목에 기록합니다.
- 같은 내용을 여러 문서에 반복하지 않고, 상세 설명이 있는 문서로 링크합니다.
- 코드 변경으로 문서의 설명이 달라지면 같은 작업에서 함께 수정합니다.
- 백엔드 전체 명세가 아니라 프론트엔드가 사용하는 요청·응답과 연동 규칙만 관리합니다.
- 도메인 문서는 컴포넌트 목록보다 사용자 흐름, 상태 전이, 입력 제약과 도메인 간 관계를 중심으로 작성합니다.
