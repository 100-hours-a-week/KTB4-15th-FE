# 찜 도메인

마지막 업데이트: 2026-10-09

## 목적

채팅에서 추천받은 상품을 저장하고 가격 변화를 확인할 수 있게 합니다.

## 사용자 흐름

- 추천 상품의 하트 버튼으로 찜을 추가하거나 해제합니다.
- 찜 목록은 최신순으로 20개씩 불러오며, 목록 끝에서 다음 페이지를 자동 조회합니다.
- 찜 목록 카드나 이미지를 누르면 외부 구매 페이지를 새 탭으로 엽니다.
- 빈 목록에서는 채팅으로 이동해 상품 추천을 받을 수 있습니다.

## 상태와 제한

- 찜은 최대 300개까지 추가할 수 있으며 FE와 BE에서 함께 제한합니다.
- 찜한 상품이 10개 이상이면 새 대화 화면에서 찜 목록 기반 코디 추천을 사용할 수 있습니다.
- 추가·해제 요청이 실패하면 현재 하트와 목록 상태를 유지하고 Toast로 안내합니다.
- 목록에서 찜을 해제하면 카드는 유지하고 하트만 변경하며, 재진입이나 새로고침 시 서버 목록을 반영합니다.
- 최초 목록 조회 실패 시 재시도 화면을, 다음 페이지 조회 실패 시 기존 목록과 하단 재시도 버튼을 표시합니다.
- 이미지가 없거나 로드에 실패하면 기본 대체 영역을 표시합니다.
- 찜한 당시 가격과 현재 가격이 다르면 당시 가격, 변동률과 현재 가격을 함께 표시합니다.

## API

| Method   | Path                      | 역할         |
| -------- | ------------------------- | ------------ |
| `GET`    | `/wishlists`              | 찜 목록 조회 |
| `GET`    | `/wishlists/count`        | 찜 개수 조회 |
| `POST`   | `/wishlists`              | 찜 추가      |
| `DELETE` | `/wishlists/{wishlistId}` | 찜 해제      |

## 관련 코드

- `src/features/wishlist`: 찜 API, Schema, Query와 목록 UI
- `src/features/chat/ui/product`: 추천 상품의 찜 버튼
- `src/app/(service)/wishlists`: 찜 목록 Route

목록 추가 조회 시 초기 서버 카드 DOM을 유지하고, 하단 로딩 영역은 스크롤 앵커에서 제외해 스크롤 위치가 새 목록 끝으로 끌려가지 않도록 한다. 다음 페이지 조회 실패 시 자동 요청을 중단하고 수동 재시도를 제공한다.

추가 조회는 하단 200px 이내로 내려가는 스크롤에서 한 번만 실행한다. 응답 후 하단이 계속 보여도 자동 조회하지 않으며, 관성 스크롤이 끝나고(200ms 동안 이동 없음) 다시 내려야 다음 페이지를 조회한다. 화면이 넓어 스크롤할 수 없거나 직접 조회하고 싶을 때는 하단의 `더 불러오기` 버튼을 사용한다.

스크롤 이벤트를 등록할 때 이미 아래로 스크롤된 위치도 한 번 확인한다. 서버 HTML에서 hydration 전에 스크롤했거나 브라우저가 스크롤 위치를 복원한 경우에도 하단에 도달했다면 한 페이지를 조회한다.
