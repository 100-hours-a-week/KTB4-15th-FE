# 랭킹

## 조회와 인증

- `/ranking`은 로그인과 프로필 완료 확인 후 표시합니다. 기본 기준은 찜순(`WISH`)이고 조회순(`CLICK`)으로 전환할 수 있습니다.
- 서버는 최초 찜순 데이터를 조회해 HTML과 초기 쿼리 데이터로 제공합니다. 조회순은 첫 선택 시 브라우저에서 조회합니다.
- 서버 조회 401은 기존 토큰 갱신 경로로 처리합니다. 나머지 서버 조회 실패는 클라이언트 조회·재시도로 복구합니다.

## 데이터 캐시

- 서버는 캐시 조회 전 `members/me`를 `no-store`로 호출해 현재 요청의 인증을 확인합니다.
- 사용자별 필드가 없는 성공한 랭킹 결과만 `unstable_cache`로 300초 재사용합니다. 키는 버전과 API URL(랭킹 기준 포함)이며 쿠키는 키와 결과에 저장하지 않고 실제 API 호출에 전달합니다.
- 기간 경과 후 요청에서 백그라운드 재검증합니다. 실패하면 기존 결과가 더 오래 유지될 수 있습니다.
- 페이지 전체 ISR이 아닌 SSR + Data Cache입니다. ECS별 캐시는 자동 공유되지 않으며 갱신 시점 차이를 허용합니다. 배포·재시작 시 보존 여부는 볼륨 구성에 따라 달라집니다.
- 초기 서버 데이터가 있는 브라우저 쿼리는 30초 동안 최신으로 취급합니다. 조회순 브라우저 호출은 서버 공통 캐시를 사용하지 않습니다.

## 표시와 점진 렌더링

- 기준별 최대 100개 데이터는 한 번에 받되 최초 HTML에는 20개 행만 포함합니다.
- 목록 끝 200px 이내에서 20개씩 추가 표시하며 추가 API 호출은 없습니다. 수동 `상품 더 보기`도 지원합니다. 다른 탭으로 전환하면 표시 개수를 초기화합니다.
- 가상화가 아니므로 끝까지 스크롤하면 전체 행이 렌더링됩니다.
- 최초 행은 서버에서 구성하고 이미지 확대와 구매 클릭은 클라이언트 액션으로 처리합니다. 재조회 이후에는 최신 쿼리 데이터로 표시합니다.
- 집계는 영어 compact 단위 K·M·B 등을 사용하고 소수점은 버립니다. 예: `1,234 → 1K`, `999,999 → 999K`.

## 이미지와 구매 링크

- 썸네일은 Next.js 기본 이미지 최적화와 `sizes="80px"`를 사용합니다.
- 이미지 URL이 있는 첫 상품 하나에만 preload와 높은 요청 우선순위를 적용하고 나머지는 lazy loading합니다.
- 이미지가 없거나 로딩에 실패하면 상품 종류에 맞는 대체 아이콘을 표시합니다.
- 확대창 코드는 동적으로 가져오며 열 때만 마운트합니다. 확대 이미지는 원본 URL을 사용합니다.
- 구매 링크는 새 탭으로 열고 클릭 집계를 요청합니다.

검증 방법은 [테스트 문서](../testing.md), 측정과 실험 이력은 [성능 개선 기록](../performance/ranking.md)을 참고합니다.
