# LOOK DDAK WCAG 2.2 AA 적합성 평가

평가일: 2026-11-10 (Asia/Seoul)

대상: FE 브랜치 `fix/wcag-aa-contrast-focus`, 기준 커밋 `97fb8b3a47b5f7bca24a1296ac408536849427c2` + 현재 작업 트리의 기존 접근성 수정

판정: **현재 AA 미충족.** 공통 색상·채팅 포커스·하단 메뉴 수정만으로 전체 서비스의 적합성을 주장할 수 없습니다.

## 2026-11-11 추가 수정 및 재검사

- 랜딩 데모와 피팅 빈 상품 그림의 글자 대비를 높였습니다. 랭킹·찜·옷장의 이미지 대체 표시에 이미지 역할을 부여했습니다.
- 랜딩 슬라이드는 방향키로 전환할 수 있습니다. 옷장 필터는 버튼 그룹에서 선택 상태를 전달하며, 옷장 본문과 채팅 오류의 의미 구조를 보완했습니다.
- 피팅 대기 화면의 장식 애니메이션은 3.2초간 한 번 재생됩니다.
- Chromium에서 18개 경로와 총 36개 화면 상태를 axe로 재검사해 A·AA 규칙 위반이 검출되지 않았습니다. 이 검사에서 추가로 발견한 옷장 본문과 채팅 오류의 의미 구조는 브라우저 회귀 테스트로 확인했습니다.
- 실제 스크린리더와 브라우저 확대, 운영 환경의 전체 사용자 흐름 검증이 남아 있습니다.

## F1~F7 수정 후 재검사

같은 브랜치에서 F1~F7을 수정했습니다. 아래 기준표는 수정 전 평가 기록입니다.

- 프로필의 파일 입력을 숨기고 기존 사진 등록 버튼에서 키보드로 파일 선택이 열리는지 확인했습니다. 피팅 진행률에는 이름을 지정했습니다.
- 피팅 링크의 이름에 선택 상품을 포함했습니다. 변경 링크와 추천 상품의 비선택 표시점에는 보조 텍스트 색을 적용했습니다. 표시점은 8px이고 클릭 영역은 24×24px입니다.
- 화면별 문서 제목을 지정하고 일반 404와 잘못된 채팅 주소의 제목을 확인했습니다. 랜딩 영어 구절에는 `lang="en"`을 지정했습니다.
- 같은 36개 상태를 Chromium·axe로 다시 검사했습니다. 변경 링크의 대비, 파일 입력 이름, 진행률 이름, 상품 버튼 크기 경고가 해소됐습니다. 랜딩 데모와 피팅 빈 상품 그림의 대비 및 랭킹 이미지 대체 표시의 ARIA 경고는 남아 있습니다.
- 이 재검사는 F1~F7의 수정 범위에 해당합니다. 전체 AA 적합 판정에는 보고서 하단의 추가 검증이 필요합니다.

## 평가 범위와 판정 의미

WCAG 2.2의 A·AA 55개 성공 기준을 모두 대조했습니다. 4.1.1은 WCAG 2.2에서 제거되었고, AAA 기준인 2.4.13은 이 평가에 포함하지 않았습니다. 기준은 [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)입니다.

- `미충족`: 검사 범위에서 구체적인 반례를 재현했습니다. 한 건의 실패만으로 해당 기준의 전체 적합 판정은 불가합니다.
- `충족(표본)`: 검사한 화면·동작에서는 충족 근거가 있습니다. 모든 데이터·상태·기기에서의 충족을 보증하지 않습니다.
- `해당 없음`: 검사 범위에 관련 콘텐츠나 기능이 없습니다.
- `추가 확인`: 부분 근거가 있으나 전체 기준을 판정할 증거가 충분하지 않습니다. 통과로 계산하지 않습니다.

이 문서는 **55개 기준을 빠짐없이 검토한 코드·브라우저 평가 보고서**입니다. 운영 환경의 전체 과정을 보조기기까지 검증한 정식 적합성 선언 또는 인증서는 아닙니다. AA 선언에는 모든 해당 A·AA 기준의 충족, 전체 페이지와 전체 과정에 대한 검증이 필요합니다.

- 로컬 Next 개발 서버 + 기존 Playwright Chromium + 설치되어 있던 axe-core 4.13.0. 의존성·설정 추가 없음.

## 확인된 문제와 최소 수정

### F1. 프로필 파일 입력에 이름이 없고 보이지 않는 Tab 정지점이 생김

- 기준: **4.1.2(A), 2.4.7(AA)**. 우선순위: P1.
- 재현: `/profile/setup`에서 이름·나이·키·몸무게·전신 사진 선택 버튼 다음으로 Tab을 누르면 1×1px 입력에 포커스가 갑니다. ARIA 스냅샷 이름은 목적 없는 `Choose File`이며 화면에는 포커스가 보이지 않습니다.
- 원인: `src/features/profile/ui/profile-photo-section.tsx:60`의 file input에 label/aria-label/hidden/tabIndex 처리가 없고 `profile-setup-form.module.scss:206`에서 clip-path로 자릅니다.

- 미수정 영향: 키보드 사용자는 현재 위치를 놓치고 보조기기 사용자는 파일 선택의 목적을 알기 어렵습니다.

### F5. 추천 상품 페이지 버튼의 클릭 영역과 점 대비가 부족함

- 기준: **2.5.8(AA), 1.4.11(AA)**. 우선순위: P2.
- 재현: AI 추천이 완료된 채팅에서 페이지 버튼은 **18×18px**, 간격 **2px**입니다. axe `target-size`가 두 버튼 모두 크기와 간격 예외를 통과하지 못한다고 보고합니다. 24px 원을 기준으로 한 간격도 부족합니다.
- 원인: `src/features/chat/ui/product/recommended-product-list.module.scss:28`의 버튼 크기와 `:39`의 회색 점. 선택되지 않은 점은 활성화 가능한 버튼임에도 유일한 시각 표시가 `#e5e8eb`이고, 페이지 배경 대비 약 **1.17:1**입니다.
- 최소 수정: 보이는 점의 8px 크기는 유지하며 클릭 영역을 24×24px 이상으로 확대하고, 비선택 점에는 배경 대비 3:1 이상의 시맨틱 색을 사용합니다. 44px은 이번 AA 최소 요건으로 요구하지 않습니다.
- 미수정 영향: 손 떨림·저시력 사용자가 페이지 전환 버튼을 발견하고 정확히 누르기 어렵습니다. [W3C 비텍스트 대비 해설](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).
- 증거: `chat-products.json`, `chat-products.png`, 소스의 pageButton/pageDot.

## 추가 확인·권장 보완

### A1. 옷장의 탭 의미와 키보드 동작

`fitting-wardrobe-screen.tsx`는 tablist/tab을 선언하지만 tabpanel·aria-controls 연결과 방향키/roving tabindex 처리가 없습니다. ArrowRight 후에도 포커스가 `상의`에 그대로 있고 모든 탭이 Tab 순서에 남는 것을 재현했습니다. 기본 Tab+Enter로 필터 실행은 가능하므로 **방향키가 없다는 이유만으로 2.1.1 실패로 세지 않았습니다.** 실제 탭 패턴을 구현하거나, 동작이 단순 필터라면 랭킹처럼 버튼 그룹·aria-pressed로 의미를 맞추는 것이 최소 보완입니다. main 부재·일부 제목 계층 경고도 보조기기로 확인해야 합니다.

### A2. 랭킹의 generic span에 aria-label 지정

`src/features/ranking/ui/ranking-row-actions.tsx:30`의 이미지 없음 span 6개에서 axe `aria-prohibited-attr`가 발생했습니다. 접근성 트리에서 generic 역할의 이름은 신뢰할 수 없습니다. 정보를 전달하려면 적절한 이미지 역할/텍스트를 제공하고 장식이면 불필요한 이름을 제거해야 합니다. 정적 span 자체를 UI 컴포넌트와 동일시해 별도 실패 기준을 추가하지 않았습니다. 제품명은 별도의 구매 링크에 남아 있습니다.

### A3. 자동 경고와 수동 판단의 경계

- 총 36개 상태에서 WCAG 태그의 자동 실패 규칙은 color-contrast, target-size, aria-progressbar-name, label, aria-prohibited-attr의 5종입니다. 상태 간 중복과 장식 예외 후보가 있으므로 자동 노드 수를 실패 기준 수로 변환하지 않았습니다.
- heading-order, region, landmark-one-main은 axe best-practice입니다. 유용한 보완 대상이지만 그것만으로 WCAG 실패를 확정하지 않았습니다.
- 모달 외부의 aria-hidden-focus incomplete는 Radix의 포커스 트랩과 함께 판단했습니다. 이름 변경 모달의 8회 Tab 순환은 모두 내부에 머물렀고 Escape로 종료되었습니다.
- 다이얼로그 진입 애니메이션 중 측정된 대비 경고는 전환 완료 후 재검사에서 사라져 제외했습니다.
- 텍스트 200% 시험에서 말줄임이 늘어나는 화면이 있습니다. 루트 폰트 확대와 실제 브라우저 확대는 다르므로 이를 곧바로 1.4.4 실패로 단정하지 않았습니다.

## 전체 적합 판정을 위해 남은 검증

1. F1~F7을 수정하고 관련 자동 검사·동작 재검증. A1/A2의 의미 구조도 정리.
2. macOS VoiceOver+Safari, Windows NVDA+Chrome/Firefox로 인증→프로필→채팅→상품 선택→사진→피팅 결과 저장·삭제까지 전체 과정 확인. 긴 가상화 채팅, 실시간 알림과 폼 오류 발화를 반드시 포함.
3. 실제 브라우저 200%·400% 확대, 320px·가로 화면, 사용자 글자 간격, 모달·BottomSheet·긴 실제 상품명/오류 문구에서 정보 손실·포커스 가림 확인.
4. 운영 API의 세션 만료/갱신·사진 검증 지연/실패·피팅 만료/완료/실패·목록 삭제/복원 절차를 확인. 사용자 통제 시간 제한 및 오류 예방 기준을 확정.
5. 남아 있는 `추가 확인`을 증거와 함께 해소하고 전체 페이지·전체 과정의 모든 해당 A·AA 기준이 충족되었을 때만 AA 적합 선언.
