# 랜딩 화면

## 범위와 구성

`/`는 공개 서비스 소개 랜딩입니다. 실제 채팅 API, 사진 업로드나 피팅 요청을 실행하지 않습니다. 이전 `/landing`과 `/onboarding`은 `/`로 영구 리다이렉트하며 온보딩 완료 쿠키는 사용하지 않습니다.

헤더 → 히어로 → 기능 소개 → FAQ → CTA·푸터 순서로 구성합니다. 시작 버튼은 클릭 시에만 기존 `getMemberMe()`와 `apiClient`로 회원 정보를 조회하고 필요한 세션 갱신 후 프로필 완료는 `/chat`, 미완료는 `/profile/setup`, 비로그인은 `/signup`으로 보냅니다. 401은 기존 apiClient가 갱신 후 재요청하며 인증 실패가 확정되면 회원가입으로 이동합니다. 그 외 오류는 로그인으로 이동합니다. 조회 중 버튼은 비활성화하며 별도의 `/start` 경로는 사용하지 않습니다. 로그인 링크는 `/login`입니다. AI 제작 사진과 전용 3D 일러스트를 사용합니다.

## 히어로

- 하나의 폰 안에서 채팅 → 초록 니트 추천 → 피팅 처리 → 동일 니트 착장 결과로 이어집니다. 가상 피팅 화면에는 뒤로가기 아이콘을 표시하지 않습니다.
- 모션 사용 시 AI 답변과 추천 카드는 CSS부터 숨겨 초기화 전 깜빡임을 막습니다. 추천 니트는 eager 로딩으로 숨겨진 카드에서도 이미지 요청을 시작합니다.
- 추천 카드의 입어보기 강조 후 니트 이미지 영역이 피팅 사진 크기로 확장됩니다. 처리 표시를 거쳐 착장 사진과 상품 설명을 함께 보여줍니다.
- 입어보기 버튼에 데모 커서가 접근해 누르면 버튼이 축소되고 ‘피팅룸으로 이동 중’으로 바뀐 뒤 니트 확장이 이어집니다. 스크롤을 되돌리면 원래 상태로 복원하고, 모션 감소 설정에서는 클릭 연출을 생략합니다.
- 데모 커서는 버튼 안쪽에 배치합니다. 추천 카드 인디케이터는 표시하지 않고 채팅 맥락을 보여주는 입력창은 작은 높이로 유지합니다.
- 피팅 결과는 ‘내 모습으로 입어봤어요’ 제목과 ‘추천받은 니트, 나에게도 이렇게.’ 설명으로 추천에서 착장으로 이어지는 맥락을 강조합니다. 기존 결과 사진은 유지하며 사진 영역을 조금 늘리고 하단 설명 여백을 줄입니다.
- 세로 스크롤 2600px에 연동하고 `scrub: 0.6`으로 전환합니다.
- 히어로와 기능 소개 모두 `anticipatePin: 1`로 스크롤 속도에 따른 고정 경계의 시각적 튐을 완화합니다. 기능 소개의 750px 대기 구간은 유지합니다.
- 데스크톱은 화면 높이에서 헤더 공간을 제외하고, 모바일은 고정 후 화면 전체를 사용하도록 100dvh 높이를 적용합니다. 초기 헤더는 스크롤로 넘어갑니다. ResizeObserver로 스테이지 높이와 너비에 맞추되 폰을 최대 1.2배까지 확대합니다. 제목과 폰은 가운데 세로 배치를 유지하며 제목 크기와 여백을 줄여 폰의 표시 높이를 확보합니다.
- 모션 화면은 제목 여백과 데모 화면 높이를 줄여 축소를 완화하며, 추천 이미지와 피팅 사진 비율도 함께 조정합니다. 모션 감소 설정의 세로 배치는 유지합니다.
- 높이 740px 이하 모바일에서는 제목과 여백도 줄입니다. 니트 전환 좌표는 축소 전 좌표로 환산해 추천 카드와 착장 영역에 맞춥니다.

## 기능 소개

찜 기반 코디 추천(찜 10개 이상), 찜순·조회순 랭킹, 피팅 완료 알림을 소개합니다.

세로 스크롤에 따라 소개 3장이 왼쪽으로 이동합니다. 각 장은 중앙에서 750px 동안 머무르고 장면 사이는 900px 동안 이동합니다. 전체 구간은 4050px입니다.

찜 이미지는 정적으로 표시하며 왕관과 알림 벨은 해당 장면 최초 진입 시에만 움직입니다.

기능 소개 이미지는 기본 lazy 로딩을 유지하고, 섹션이 화면에서 600px 이내로 접근하면 IntersectionObserver로 전체 이미지의 loading을 eager로 전환합니다. 첫 진입부터 eager 로딩을 강제하지 않고 가로 슬라이드의 다음 이미지도 미리 준비합니다. 실제 lazy 요청 시점은 브라우저가 결정합니다.

## FAQ와 마지막 영역

- FAQ는 네 가지 질문을 기본 HTML details/summary로 제공합니다. 키보드 조작을 유지하고 지원 브라우저에서는 높이·투명도를 300ms 동안 전환합니다. 미지원 브라우저에서는 즉시 열고 닫습니다.
- FAQ는 최소 100svh 높이에서 내용을 세로 중앙 정렬하고 답변이 늘어나면 영역도 늘어납니다.
- CTA와 푸터 묶음은 최소 100svh를 채웁니다. CTA는 연한 초록, 푸터는 FAQ와 같은 아이보리 배경과 상단 구분선으로 영역을 구분합니다. FAQ와 CTA에는 스크롤 고정을 적용하지 않습니다.
- 푸터에는 작은 브랜드명, 문의 이메일과 AI 연출 이미지 안내를 표시합니다. 모바일에서는 세로로 배치합니다.

## 브라우저 배경

Feature 앞뒤와 FAQ → CTA 경계는 80px 그라데이션으로 연결하고, 고정 중에는 하단 배경을 연두색으로 연장합니다. 랜딩은 화면 중앙에 표시되는 섹션의 배경색을 html·body와 theme-color에 0.4초 동안 전환해 반영합니다. 모션 감소 설정에서는 즉시 전환합니다. FAQ와 CTA도 각각 명시한 배경색으로 전환하며, 푸터의 배경과 구분선은 유지합니다. 화면을 떠나면 기존 색으로 복원합니다. 기능 소개는 ScrollTrigger의 고정 높이보다 100dvh를 우선해 Safari 주소창 변화에 대응합니다. Safari 브라우저 UI의 실제 색상 반영은 기기 확인이 필요합니다.

## 모션 감소와 검증

모션 감소 설정에서는 스크롤 고정과 폰 축소를 적용하지 않습니다. 채팅과 착장을 함께 세로로 표시하고 기능 소개도 세로로 펼칩니다. FAQ는 즉시 개폐합니다.

`tests/e2e/landing.spec.ts`에서 스크롤 전환, 최초 진입 애니메이션, FAQ 키보드 조작, 모션 감소 배치와 짧은 모바일·데스크톱 화면의 폰 표시 및 피팅 정렬을 검증합니다. 기존 쿠키 유무와 관계없는 루트 표시, 이전 주소 리다이렉트, 인증·프로필 상태별 시작 링크 이동도 검증합니다. 실제 기기에서의 성능 측정은 별도입니다.

CTA와 푸터는 각각 `landing-cta.tsx`, `landing-footer.tsx`와 전용 SCSS Module로 분리합니다. 두 영역의 최소 화면 높이를 관리하는 closing 레이아웃은 `landing-screen`에 둡니다.
