# 화면별 CSS 분리

## 결과와 원인

2026-11-16, 같은 작업 트리와 환경에서 Next.js 16.3.5 / Turbopack 프로덕션 빌드를 비교했습니다. `/fitting`에 채팅·회원가입·랭킹 등의 CSS가 초기 연결되는 현상이 있었고 원인은 두 가지였습니다.

1. 피팅·찜 mutation을 기능의 `index.ts`에서 가져오면 같은 파일이 재수출하는 화면 UI까지 CSS 그래프에 연결됩니다. 예를 들어 채팅 추천 상품 카드는 피팅·찜 mutation을 각각 공통 index에서 가져오고, 그 index는 옷장·결과·찜 화면을 함께 재수출했습니다. 피팅 진행 화면의 프로필 Query, 알림 카드의 피팅 mutation, 계정 화면의 로그아웃 mutation에도 같은 연결이 있었습니다.
2. 기본 CSS chunking은 요청 수를 줄이려고 서로 다른 경로의 CSS도 공유 청크로 합칩니다. 기본 빌드에서 루트 레이아웃에 연결된 두 청크에 다른 화면 스타일이 섞여 있었습니다. 직접 import만으로는 이 합침이 없어지지 않았습니다.

기능별 화면을 호출하는 페이지와 기능 간 mutation·Query import를 실제 파일로 연결했습니다. 전체 소스·테스트·설정의 정적 import, 재수출, 동적 import, require 참조를 확인해 사용하지 않는 기능별 index 7개(auth·chat·fitting·notification·profile·ranking·wishlist)는 삭제했습니다. 후속 사용자 요청으로 member·product 및 공통 UI index도 직접 import로 전환했습니다. 총 22개의 재수출 index를 삭제했고, 구현을 담은 `pagination-status/index.tsx`는 `pagination-status.tsx`로 옮겼습니다. 아래 수치는 이 후속 정리 이전의 CSS 분리 측정값이며 index 전체 제거 후 LCP 효과를 의미하지 않습니다. 컴포넌트·상태·API 동작, CSS 선택자 자체는 변경하지 않았습니다.

공통 빌드 설정은 `experimental.cssChunking: { type: "graph", requestCost: 1000 }`입니다. 기존 2026-10-27 [graph 기본값 실험](./fitting-wardrobe.md)과 달리 import 연결을 먼저 분리하고 합침 비용도 낮췄습니다. 현재 Next 버전에서 지원하는 실험 옵션이므로 업그레이드할 때 빌드와 CSS 경계 테스트를 다시 실행합니다.

## 검증과 재현

- `pnpm build`: 최종 설정의 Turbopack 프로덕션 빌드 통과
- `pnpm test:css`: 빌드 이후 피팅·채팅·옷장·로그인·랭킹의 필수 CSS와 다른 화면 전용 CSS 배제 검증 5개 통과
- `pnpm test`: 단위 테스트 26개 통과
- `pnpm lint`, `pnpm type-check`: 통과
- `pnpm check`: 기존 `performance-results/chat-lcp/` 결과 JSON 187개 포맷 문제로 중단. 성능 로그를 일괄 수정하지 않았습니다. 이번 변경 파일의 포맷 검사는 별도로 통과했습니다.
- 전용 mock API와 실제 최종 프로덕션 서버로 피팅·옷장·새 채팅·대화·검색·랭킹·찜·로그인·회원가입·마이페이지·알림·프로필 설정 12개 경로를 390px/1280px에서 확인했습니다. 각 화면의 CSS 응답·스타일시트 로드와 스크린샷을 확인했습니다. 실제 사용자 API·S3는 사용하지 않았습니다.

- 기존 사진 변경 버튼 E2E는 320px·390px·1280px에서 3개 통과했습니다. 채팅 추천 상품 E2E 2개는 임시 mock 연결 환경에서 채팅방 조회·생성이 실패해 통과하지 못했습니다. 해당 기능의 정상 동작 검증은 남아 있습니다.

```bash
pnpm build
pnpm test:css
```

이 변경은 요청 수를 늘리는 대신 초기 CSS 전송량을 줄입니다. 초기 방문에서 연결 CSS가 늘었으며 네트워크 환경에 따라 지연이 증가할 수도 있습니다. 클라이언트에서 이미 방문한 화면의 CSS가 유지되는 동작을 없앤 것은 아닙니다. Lighthouse LCP·FCP 전후 측정과 실제 기기·운영 검증은 아직 하지 않았으므로 용량 감소를 LCP 개선으로 표현하지 않습니다.

## index 전체 제거 후 검증 (2026-11-17)

- 소스의 index.ts/index.tsx를 모두 제거하고 정적·동적 import를 구현 파일로 변경했습니다. pagination-status 구현은 이름을 바꿔 보존했습니다.
- 프로덕션 빌드(TypeScript 포함), 린트, 단위 테스트 26개, CSS 경계 테스트 5개를 통과했습니다. 전체 소스·테스트의 로컬 import 해석도 확인했습니다.
- 전체 포맷 검사는 기존 performance-results JSON 문제로 통과하지 못했습니다. 이 정리 후 브라우저 기능과 LCP는 재측정하지 않았습니다.

## develop 기준 분리 (2026-11-17)

이 변경은 develop의 `6fac5f3`을 기준으로 별도 브랜치에 옮겼습니다. 피팅 SSR 프로필 초기 데이터, 사진 처리 모달 동적 로딩, 스피너 디자인 변경은 가져오지 않았습니다. 충돌은 develop의 동작을 유지하며 import만 바꿨고, develop에 구현으로 남아 있던 `spinner/index.tsx`는 `spinner.tsx`로 이름만 바꿨습니다. 위 용량 표와 브라우저 검증은 기존 피팅 브랜치에서 측정한 기록이므로 이 develop 기반 브랜치의 실측 결과로 해석하지 않습니다.
