# 피팅 옷장 CSS graph 실험

## 결과

2026-10-27, 액션 분리 기준 커밋 `73e41bd`에서 `experimental.cssChunking: "graph"`만 바꾸어 프로덕션 빌드를 비교했습니다. CSS 용량은 줄었지만 요청 수가 늘었고 간이 브라우저 비교에서 표시 시간 개선을 확인하지 못해 기본 설정을 유지합니다.

## 빌드 비교

라우트의 `page_client-reference-manifest.js`에 연결된 CSS 경로를 중복 제거하고 파일 크기를 합산했습니다. gzip 크기는 로컬 압축 추정치이며 실제 HTTP 전송량과 다를 수 있습니다.

## 브라우저 간이 비교

- 각 빌드 5회, Chromium의 매회 새 Context와 비활성 HTTP 캐시를 사용했습니다.
- 화면 412×915, DPR 2, CPU 4배 제한, 네트워크 지연 60ms·다운로드 1012500 bytes/s·업로드 168750 bytes/s로 고정했습니다.
- `/fitting/wardrobe?itemType=TOP`에 테스트 API의 상의 1개를 표시했습니다. 상품 이미지는 동일한 회색 SVG로 대체했고 첫 방문 이미지는 실제 CDN·최적화 처리 시간을 측정하지 않습니다.
- 각 측정은 이동 완료와 카드 표시 후 1.2초 더 관찰했습니다. 기본 5회를 먼저 측정하고 graph 5회를 측정했으므로 실행 순서에 따른 환경 변동을 배제할 수 없습니다.

| 중앙값     |  기본 | graph |
| ---------- | ----: | ----: |
| FCP        | 208ms | 252ms |
| 관찰된 LCP | 472ms | 620ms |

두 화면의 스크린샷을 확인했고 카드 선택의 `aria-pressed` 변경도 통과했습니다. 이 결과는 실제 상품 20개를 사용하는 Lighthouse 모바일 시뮬레이션 결과와 직접 비교하지 않습니다. TBT와 실제 Lighthouse 점수는 이번 실험에서 측정하지 않았습니다.

## 판단과 재현

- 기본 graph 설정의 CSS 용량 감소만으로 로딩 속도 개선을 주장하지 않습니다. 현재는 기본 설정으로 복원했습니다.
- 실제 환경에서 다시 비교하려면 기준 커밋으로 빌드·측정한 다음 `next.config.ts`에 `experimental: { cssChunking: "graph" }`만 추가하고 다시 빌드합니다. 상품·필터·뷰포트·브라우저 및 이미지 최적화 캐시 조건을 맞추고 전후를 번갈아 측정합니다.
- graph의 비용 조정 옵션은 이번 범위에서 시험하지 않았습니다.
